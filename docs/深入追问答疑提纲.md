# 从一个错字深入讲解 OCR 可靠性

本提纲对应网站“深入追问”七问路径。示意字符串、评分表和网页计算均为教学构造；24图评测协议尚未执行。不要把示意数值写成实际识别效果。

## 先用半分钟讲主线

OCR 的检测与识别分别可能漏字、读错。先约定参照和计分规则，再用字符错误率衡量文本差异；但同样的字符错误率可能对应不同的编号结果，因此还要查目标字段。模型分数也不是天然的正确概率。筛掉低分结果时，要同时报告留下了多少输入、留下的错了多少。最后，所有判断都要回到独立对象组、配对输入和可追溯的实际记录。

## 用三分钟讲清反例

打开 `#inquiry?step=d-field-check`，先选“错在标题”，再选“错在编号”。

| 项目 | 错在标题 | 错在编号 |
|---|---|---|
| 人工参照 | 项目代号Q105 | 项目代号Q105 |
| 人工候选 | 项日代号Q105 | 项目代号Q1O5 |
| 最小编辑 | 1次替换 | 1次替换 |
| 参照长度 | 8 | 8 |
| CER | 1/8 = 12.5% | 1/8 = 12.5% |
| 预先标出的编号完整匹配 | 1/1 | 0/1 |

先请对方指出错在哪，再解释：CER统计的是编辑代价，不区分字符处在哪个字段。这个极小例子说明两种指标回答的问题不同，不能估计真实场景的发生率和后果。编号字段在例子中预先标注；网页没有实现通用字段抽取，更没有处理真实照片。

若继续问“是不是只查编号就够了”，回答：还需检查漏行、重复字段、字段定位、其它文字及人能否核对，不能用一个指标替代整个任务。

## 再用三分钟解释阈值

打开 `#inquiry?step=d-abstain`。表中8项分数与正误均为人工构造，其中H没有输出。

1. 阈值0.95时，保留A/B/C三项，覆盖3/8=37.5%；其中B错误，保留项错误比例1/3≈33.3%。这不是模型实测。
2. 阈值升到1.00时，一项也没保留。覆盖0/8=0%，但错误比例的分母为0，必须说“未定义”，不能说“零错误所以可靠”。
3. 阈值0.99时，只剩1项且该项预设为正确。这只是构造表中的一项，不能推广成真实模型或总体的保证。

若问“分数0.98是否等于98%正确”，先问清分数对应的单位与工具定义；再解释校准需要独立数据和正确判据。校准研究的分类实验不等于我们使用的OCR已经校准。

## 可能被追问的边界

| 追问 | 回答要点 |
|---|---|
| CER能不能超过100%？ | 能。参照A、候选AAAA，需要插入3字符，CER=3/1=300%。它是错误率计数，不是正确概率。 |
| 最小编辑代价怎样算？ | 将两串拆成前缀，考虑最后一步是匹配/替换、删除或插入，取三种候选代价的最小值；空前缀的边界就是需要插入/删除的数量。网站第三问可展开递推式。 |
| 两张图的CER能直接平均吗？ | 先说明权重。本协议合并错误数与参照长度：人工例子为10字符错1个、90字符错0个，合计1/100=1%；逐图百分比简单平均为5%，含义不同。 |
| 没有参照字符怎么算？ | 本演示记为未定义，并保留原始计数。评分规则需提前明确，不能把无法评分当成完美。 |
| 整行漏检怎么办？ | 从完整参照与输入台账出发，不能只统计返回的行；示意中空输出对应删除。真实多区域任务还需区域匹配规则。 |
| 为什么O和0不统一？ | 这会改变测量目标，可能掩盖差异。本演示不合并；若真实方案要归一化，应预先说明并保留原始串。 |
| 提高阈值能保证错误更少吗？ | 保留数量不会增加，但有限样本中的错误比例不保证逐点下降；必须看分母和具体数据。 |
| 24张图是否足够？ | 只是检查评测流程的教学试点，来自6个对象，不能说24个独立对象，也不能推出医疗有效性。 |
| 为什么按对象划分？ | 减少同一对象的近似图像跨开发与测试；这不能消除全部预训练重叠或场景偏差。 |
| 真实实验做了吗？ | 尚未。网页只新增可验证的计算与协议，真实图像、工具输出和用户观察仍需执行者记录。 |

## 把答疑落到可执行的下一步

末问 `#inquiry?step=c-ocr-protocol` 提供待讨论的设计：6个人工编号标签对象×2光照条件×2次拍摄，共24图；按对象分4个开发组对象、2个保留测试对象。同图原始与处理版本逐对比较，只在开发组选择处理与阈值，再冻结配置检查保留组。

下载 `assets/ocr-evaluation-template.csv`，它只有表头。实施者需补原图、参照、分组、版本、原始输出、计数与异常。示意标签不能覆盖真实药盒的字体、曲面、反光与布局，真实场景和目标用户核对任务需要另行设计。

## 四份资料如何使用

- [PaddleOCR 官方流水线文档](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html)：核对模块、分数及过滤输出，不证明本组选题的性能。
- [TorchMetrics：CER定义](https://lightning.ai/docs/torchmetrics/stable/text/char_error_rate.html)：核对S/D/I/N计算。本页借此计算人工字符串差异。
- [Guo 等，ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)：说明校准问题的研究背景，不把分类实验当成OCR验证。
- [Geifman 与 El-Yaniv，NeurIPS 2017](https://proceedings.neurips.cc/paper/2017/file/4a8423d5e91fda00bb7e46540e2b0cf1-Paper.pdf)：正文§2区分覆盖与选择性风险。本页只借用区分方法，没有复现其保证风险的算法。

网站中的来源、问题和回答共用 `data.js`。修改追问顺序或事实时，应先更新该文件，再更新图源和必要说明。
